# Capstone Project: Sensor to Web

## The Big Picture

You will build a complete data pipeline that:

1. **Collects data** from a hardware sensor
2. **Stores it** in a database
3. **Displays it** on a web dashboard

This is the kind of system you'd find in IoT applications, environmental monitoring, home automation, and industrial settings.

---
## The Three Pieces

### 1. Hardware Sensor

A physical device that measures something and sends data over WiFi.

**Options:**
- Use a sensor you already own (Arduino, Raspberry Pi, ESP32, etc.)
- Purchase an ESP32 + DHT22 (~$20) — we'll provide links
- Other sensors: temperature, humidity, light, motion, air quality, etc.


### 2. Backend + Database

A server that receives sensor data and stores it.

**Components:**
- REST API (FastAPI or Flask) to receive data
- Database for time-series data (MongoDB, PostgreSQL, InfluxDB, etc.)
- Structured logging
- CI/CD pipeline (GitHub Actions)

### 3. Web Dashboard

A frontend that displays your sensor data.

**Could be:**
- Simple Flask templates with charts
- React/Vue single-page app
- Real-time updates (stretch goal)

## Example Architectures

### Simple Version
```
Sensor (ESP32 + DHT22)
    ↓ HTTP POST every 60 seconds
Flask API
    ↓ stores readings
MongoDB
    ↓ queries
Flask Dashboard (renders charts)
```

### Fancier Version
```
Sensor (Raspberry Pi + multiple sensors)
    ↓ HTTP POST every 10 seconds
FastAPI
    ↓ stores readings
InfluxDB (time-series optimized)
    ↓ queries
React Dashboard (real-time charts)
```
## Other Requirements

### Spec Files

You _must_ create one or more spec files that _completely_ define the system including

* Use cases
* Data transfer
* Data models
* API specs
* Unit testing
* Cloud deployment

The benchmark for knowing if your documentation is sufficient is whether Claude Code (my preferred
generative AI coding tool) can reproduce a working version project from scratch. Sample spec files have been provided.

### Token Protection

You _must_ be able to send data over WiFi (HTTP requests to your API). All data
transfers must be password or token-protected. That means that no-one else's code should be able to access your data, backend, or front end. Secure the system

### Cloud Deployment / Docker

Most of your code should run in the cloud. As students you should be able to get free cloud credits (Amazon Web Services, Azure, Google Cloud, other) to serve your app. Cloud deployment using Docker will probably be easiest.

### ReadMe

Your project must have a detailed readme document. Its ok if the readme is generated by AI from your spec files. The readme should explain how to deploy, run, maintain, and troubleshoot your project.
